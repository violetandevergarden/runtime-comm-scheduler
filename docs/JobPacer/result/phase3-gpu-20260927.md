| 每次消息 | service p50 | API 调用 p50 |
| ---: | ---: | ---: |
| 4 KiB | 54.35 μs | 37.41 μs |

4 KiB×32 固定链的 5 组 minimal/diagnostic 对照都成功。median makespan 分别为 173.316 ms 和 178.744 ms；paired ratio minimal/diagnostic 的 seed-block median 为 0.943，5 个 block 的 bootstrap 区间为 0.914–0.975。diagnostic 在这组输入上有可见扰动，正式 G2/G3 使用 minimal。

零 jitter L0 运行噪声批次完成 30/30。全样本 median 31.209 ms，范围 23.268–36.510 ms。batch runner 不支持相同 arm 的双标签 A/B；本批按每个 seed 的前 3 次与后 3 次分组作控制性对照，没有实现计划中的 A/B 交错，因此这部分不作为严格交错噪声设计。

## G3：L0/L1 pilot 与主矩阵

Pilot 完成 18/18，主矩阵完成 90/90；主矩阵按每场景 5 个 execution seeds × 3 repeats，jitter 0.3，三个 arm 为 old-fifo、new-static_fifo、new-fifo。L1 的三个 pilot block 均显示目标机制：Static FIFO 等待 job-0/comm-0 队首；new FIFO 在该任务 ready 前先处理 job-1 的通信，且两 rank 顺序和数据校验一致。

| 场景 | old-fifo median | new-static_fifo median | new-fifo median | new static/new FIFO paired ratio |
| --- | ---: | ---: | ---: | ---: |
| L0 | 13.916 ms | 31.977 ms | 28.180 ms | 1.067；95% seed-block bootstrap 0.971–1.182 |
| L1 | 25.823 ms | 48.801 ms | 34.626 ms | 1.421；95% seed-block bootstrap 1.316–1.494 |

L1 中 new FIFO 相对同 runtime Static FIFO 有稳定的 pilot/main 机制收益；L0 的 paired 区间跨 1。两个场景的新 FIFO 中位数都慢于旧路径：L0 为 28.180 ms 对 13.916 ms，L1 为 34.626 ms 对 25.823 ms。因此这些样本支持“新 runtime 内部调度可能改善 L1”，不支持“新 runtime 整体比旧路径快”。每场景只有五个 seed block，结果仍属探索规模。

## R8/G4：真实 CUDA compute 与 S lane

旧 replay_worker 增加可选 S lane，默认 H lane 的 consumer sleep/wait 顺序保留。S lane 在应用 release 前创建并预热固定次数的 1024×1024 matmul 和 producer/consumer stream；执行时先查询 producer event 至物理完成，再提交同 seed 的独立 matmul 与 NCCL。consumer stream 上调用旧 Work.wait() 建立 NCCL 依赖，同时等待 matmul event，再对 all-reduce tensor 做真实 torch.sum 消费。每项的 terminal consumer CUDA event 定义应用完成；事后校验 CUDA consumer scalar 与 all-reduce tensor。旧 S lane 双卡 smoke 及正式 run 的 collective/consumer 校验均通过。

离线 CUDA event 校准中，1024×1024 matmul 的 1-repeat p50 在两张卡上分别为 0.0614/0.0625 ms（约 0.51×/0.52× 1 MiB NCCL profile p50）；9-repeat 为 0.4239/0.4188 ms（约 3.52×/3.48×）。high 档略低于预设约 4×。

正式执行按每个 seed/repeat 随机交错三臂，固定相同 epoch、算子形状、repeats、matmul 种子、warmup 5、profile 和 minimal observation。low/high × old static FIFO/new Static FIFO/new FIFO × 3 seeds × 3 repeats，共 **54 个有效 replay**。共尝试 57 次：high 的 s6700-r1 旧 launcher 遇到 rendezvous 端口 EADDRINUSE，rank 1 超时；整组三臂重跑后通过。失败记录在 runs.jsonl 与 stdout/stderr 中，统计只用完整成功的配对 block。

| 计算档 | old static FIFO S | new Static FIFO S | new FIFO S | FIFO−Static paired median | FIFO/Static paired median ratio |
| --- | ---: | ---: | ---: | ---: | ---: |
| low | 6.299 ms | 28.111 ms | 29.608 ms | +0.621 ms | 1.022 |
| high | 6.904 ms | 28.450 ms | 28.261 ms | −2.132 ms | 0.925 |

每档有 9 个配对点（3 seeds × 3 repeats），未作强推断。每 seed 的 FIFO−Static 中位差：low 为 +2.978、+9.928、−2.317 ms；high 为 −0.189、−5.658、−3.645 ms。三个 high seed 的中位差都偏向 new FIFO，但 9 个配对 repeat 的差值范围仍跨零（−11.343 到 +4.286 ms）。相对旧 S lane，new Static 的 makespan 中位约慢 4.2–4.3×，new FIFO 约慢 4.0–4.6×；这是整个新旧路径差异，不能归因为纯调度开销。结果支持“高算力档下 new FIFO 有探索性优势”，不支持新 runtime 比旧路径快。

每个计算档、每个 arm 有 72 个 independent-compute device-event 样本（4 tasks × 2 ranks × 9 run）。independent matmul event 中位数：low old/static/FIFO 分别为 0.454/0.579/0.636 ms；high 为 0.999/1.321/1.159 ms。运行中的时间比无竞争校准更长，范围也较宽，固定算子重复数比预先调到精确目标时间更可复现。

### 设备 timeline overlap 诊断

主机没有 nsys、nvprof 或 ncu；使用虚拟环境自带 torch.profiler 导出 Kineto Chrome trace。另以 epoch 69000、high 档对每个 arm 各做一次诊断 replay，未计入 54 个性能样本。按同一 rank、同一 GPU 的 kernel 时间戳求交，剔除每 rank 20 个 matmul warmup 和 10 个 NCCL warmup，只统计 36 个 matmul 与 4 个 1 MiB all-reduce kernel：

| Arm | rank 0 matmul overlap | rank 1 matmul overlap |
| --- | ---: | ---: |
| old static FIFO S | 0 / 36 | 3 / 36；合计 158.529 μs（rank 1 matmul device time 的 8.99%） |
| new Static FIFO S | 0 / 36 | 0 / 36 |
| new FIFO S | 1 / 36；合计 1.439 μs（0.086%） | 0 / 36 |

这说明 timeline 中确实出现过少量重叠，但新 runtime 的这两条 trace 没有可观的 kernel overlap；单次诊断也不能代表重复运行的稳定比例。G4 的三臂运行、正确性边界和 overlap 检查已完成，结论是**没有证明新 runtime 获得有效或可重复的 GPU engine overlap**。完整 trace 和区间计算见 benchmark/phase3/results/gpu-readiness/preflight-20260927-c1d5008/batches/g4-three-arm-final/ 中的 profiler/、tables/g4-device-overlap.json、tables/g4-three-arm-summary.json。

## R9/G5：DAG bridge 与 diamond

Linear→DAG bridge 完成 3 组配对、共 6/6 run；两边都执行 1 MiB NCCL 与相同的 1024×1024、1-repeat matmul。Linear 使用 S lane，DAG 使用 CUDA completion token。三组均通过数值和任务集合校验，DAG 中每 rank 的 c0/c1 都由 cuda_compute_event_query 完成后才推进，group 顺序投影与输入映射一致。

Diamond 的 Static FIFO/FIFO 各 3 次，6/6 成功；所有 rank 都完成 root、comm-a、independent、join、comm-b。另有两条 diagnostic run。事件顺序显示 root compute event 完成后发出 comm-a 与 independent；comm-a 与 independent 都完成后 join 才 ready，join compute event 完成后才发出 comm-b。两个策略均为数据正确。
